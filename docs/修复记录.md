## 2026-10-14 · 新增「去AI风卡」类型（去 AI 味）

- **现象（诉求）**：生成的小说 AI 味偏重——套路词（仿佛/似乎/不禁/那一刻）、空洞总结式金句、每段强行升华或灌鸡汤、千篇一律的对仗排比。
- **根因**：素材卡体系只有「文风卡」描述「要什么风格」，没有「不要什么」的负面清单；写作/润色节点缺乏对 AI 套路的硬约束。
- **改动**（类型单一映射源 `project.CARD_TYPES` 级联，无需逐个接口改）：
  - 新增卡片类型 `anti_ai`（`anti_ai.json`，标签「去AI风卡」），`CARD_FIELDS = ["id","title","content"]`；`state.CollabNovelState` 增 `anti_ai_cards`；`start_session` 装入该卡。
  - `prompts.build_writer_prompt` / `build_style_edit_prompt` 注入「去AI风卡」并各加一条规避要求（写作节点第 7 条、润色节点第 5 条）。
  - CLI `run_chapter.py write` 增 `--anti-ai`（id 过滤），`setup` 向导自动覆盖该类；`md_to_cards.py` 增 `CARD_SCHEMA`/`SECTION_KEYWORDS`（二级标题含「去AI风/去AI味/反AI/AI味…」即识别），模板补示例。
  - 前端 `store.js` / `CardsDrawer.vue`：类型标签、拆书统计映射、卡片预览、MD 导入提示均补「去AI风卡」；`api_write_start` 透传 `anti_ai_ids`。
  - 文档：README / 设计文档（含架构拆分刷新）/ 开发指南 / 本记录同步。
- **验证方法**（系统 Python 仅做语法与存储层校验，无需 LangChain）：
  ```bash
  cd backend && python -m py_compile project.py state.py collab_novel_agent.py api_write.py prompts.py run_chapter.py md_to_cards.py
  python -c "import project as p, tempfile; d=tempfile.mkdtemp(); p.ensure_project(d); \
    k=p.create_card(d,'anti_ai',{'title':'规避套路','content':'少用仿佛/似乎'}); \
    assert any(i.get('id')==k for i in p.load_cards(d,'anti_ai')); print('OK anti_ai round-trip')"
  cd ../web && npm run build   # 前端构建通过
  ```
- **影响范围**：新增一类素材卡；写作与润色正文风格受该卡约束（空卡则行为不变）。拆书解析不自动抽取去AI风卡（它属于作者编写的负面清单，非小说内可提炼设定）。

## 2026-10-13 · 卡片隔离泄漏（项目会混入全局演示卡）

- **现象**：新建空项目、或把某类素材卡删光后开始写作，生成的提示里会冒出全局演示角色「陆青崖」等，
  即错误带入 `backend/data/` 下的演示卡。
- **根因**：`collab_novel_agent.load_context_node` 用
  `state.get("character_cards") or load_card_file("characters.json")`——
  空列表 `[]` 在 `or` 里为假值，于是回退到**默认 `DATA_DIR`（全局演示）**。
  问题不只人物卡：`plot/style/foreshadowing/worldview` 同理，但只要某类为空就会泄漏全局演示卡。
- **改动**：改为严格使用 `state` 中已按项目目录解析好的 `cards_dir`，不再回退默认目录；
  同时 `start_session` 已经把 `cards_dir`/`chapters_dir` 正确指向 `<project>/cards`、`<project>/chapters`。
  提交：`1812045`（commit message: `fix: 修复 load_context_node 回退读取默认 data 目录导致项目混入全局演示卡`）。
- **验证方法**（用 `.venv\Scripts\python.exe`）：
  ```python
  import tempfile, project as proj, collab_novel_agent as A
  d = tempfile.mkdtemp()
  proj.ensure_project(d, seed_demo=False)                       # 空项目
  st  = A.start_session(chapter_title="t", chapter_outline="o", project_dir=d)["state"]
  ctx = A.load_context_node(st)
  assert len(ctx["character_cards"]) == 0                       # 修复前=1（泄漏）
  assert len(ctx["worldview_cards"]) == 0
  # 有卡项目 / 演示模式各自正确：有卡=1、演示模式=1
  ```
- **影响范围**：仅创作上下文加载；不影响卡片 CRUD 与章节文件。

## 2026-10-13 · `create_card` 不写回 id（新建卡无法按 id 删除/合并）

- **现象**：通过 API 或导入新建素材卡后，若卡片没自带 `id`，后续「按 id 删除」删不掉，或导入合并时
  匹配不到同一条（计数显示异常）。
- **根因**：`project.create_card` 生成随机 `key = f"{ctype[:3]}_{uuid...}"` 并写进文件，
  **却没有 `card["id"] = key` 写回卡对象本身**；`load_cards` 读回的条目缺 `id`，
  删除/合并按 `id` 匹配时失配。
- **改动**：在 `create_card` 内追加 `card["id"] = key`（仅在调用方未提供 id 时生成）。
  提交：`3052702`（commit message: `fix: 修复 create_card 生成 key 后未写回卡片 id 导致删除/合并失配`）。
- **验证方法**（用 `.venv\Scripts\python.exe`）：
  ```python
  import tempfile, project as proj
  d = tempfile.mkdtemp(); proj.ensure_project(d)
  key = proj.create_card(d, "character", {"name": "新角色"})     # 不传 id
  items = proj.load_cards(d, "character")
  assert any(it.get("id") == key for it in items)               # 修复前为 False
  # 再删：proj.delete_card 按 id 现在能正确命中
  ```
- **影响范围**：卡片存储层；修复后「新建→删除」「导入合并」链路一致。
