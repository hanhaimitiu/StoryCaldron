# StoryCaldron 开发指南

> 目的：说清本地环境如何搭起来、如何跑起来、如何调试，避免「换人不明的解释器/依赖」导致踩坑。
> 最后更新：2026-10-13。

## 1. 运行环境

| 组件 | 要求 | 说明 |
|------|------|------|
| Python | 3.10+ | **必须用项目内的虚拟环境**，见下。 |
| Node | 18+ | 仅前端开发/构建需要。 |
| 推理服务 | 兼容 OpenAI 的 `/v1`（默认 llama.cpp `localhost:8080`） | 跑「写作」才需要；纯管理接口不需要。 |

## 2. 重要的解释器（踩坑点）

本项目的 Python 依赖（langchain / langgraph 等）装在**项目内的虚拟环境**，不是系统 Python：

```
.venv\Scripts\python.exe        # Windows
.venv/bin/python                # Linux/macOS
```

所有后端命令都要用这个解释器，否则会 `ModuleNotFoundError: langchain` 之类。

```powershell
# 激活（可选，激活后直接用 python）
. .venv\Scripts\Activate.ps1
# 或不激活，全程写全路径
.venv\Scripts\python.exe backend/web_server.py
```

依赖清单见 `requirements.txt`；若 `.venv` 缺失，重建：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 3. 启动后端服务

```powershell
cd backend
.venv\Scripts\python.exe web_server.py
# 默认监听 http://127.0.0.1:8765
# 自定义端口： $env:PORT=9000; .venv\Scripts\python.exe web_server.py
```

启动后可用 `curl` 或 PowerShell `Invoke-RestMethod` 验证：

```powershell
(Invoke-RestMethod http://127.0.0.1:8765/api/health).ok   # 应返回 True
```

> 服务同时托管 `web/dist` 静态产物；没构建过时访问根路径会给开发提示（用 `npm run dev`）。

## 4. 启动前端

```powershell
cd web
npm install          # 首次
npm run dev          # 开发服务器 5173，/api 已代理到 8765
# 或生产构建：npm run build  ->  产物在 web/dist，由后端托管
```

## 5. 跑通「写作」（需要推理服务）

默认 `collab_novel_agent.get_llm` 指向本地 llama.cpp：

```powershell
# 默认即 localhost:8080/v1，key=dummy；改云端/其它服务用环境变量：
$env:LLM_BASE_URL = "http://localhost:8080/v1"
$env:LLM_MODEL    = "你的模型名"
$env:LLM_API_KEY  = "dummy"
```

无推理服务时，LLM 调用会失败并降级返回空串，写作流程**不会崩**但产出为空——这是预期降级，不是 bug。

## 6. 不依赖真实 LLM 的冒烟测试（推荐日常验证用）

把 `_call_llm` 桩掉即可跑通整张图，验证「图编排/中断恢复/落盘」逻辑是否被破坏：

```python
# backend/_smoke.py（临时）
import tempfile, collab_novel_agent as A, project as proj
A._call_llm = lambda prompt, system="", temperature=0.7: "一段测试正文。"
d = tempfile.mkdtemp()
proj.ensure_project(d, seed_demo=True)
st = A.start_session(chapter_title="测试", chapter_outline="o", project_dir=d)["state"]
final = A.run_session(st, auto_approve_human=True)
print(len(final["final_chapter"]), final["error_msg"])   # 应 >0，error_msg 为 None
```

更完整的两场景（自动通过 + 人工 revise）示例见《修复记录》中「验证方法」。

## 7. 调试与定位技巧

- **接口报错 500**：响应体带 `trace`（完整堆栈）。把 `trace` 贴出来即可定位到 `web_server.py` 哪一行。
- **写作卡住/空产出**：先看是否起了推理服务；再看 `load_context` 打印的「人物卡 N 条…」确认素材是否正确加载（**已修复**空项目不再混入全局演示卡）。
- **前端读不到卡片**：确认接口返回的是 `types`/`fields`（前端 `store.js` 读 `d.types`），不是 `cardTypes`。
- **删除卡片无效**：确认卡片有 `id`（`create_card` 生成后会写回卡内，见《修复记录》）。
- 后端日志直接打到控制台；前端用浏览器 DevTools 看 `/api/*` 请求与 `store` 状态。

## 8. 改动规范（与《修复记录》配合）

- 任何功能性改动先在对应文档登记（设计文档改结构、修复记录登 bug）。
- 后端改动保持「`project.py` 纯文件层、`collab_novel_agent.py` 编排层、`web_server.py` 仅 HTTP 薄层」的分层，不要把文件 IO 写进 `web_server.py`。
- 新增卡片类型需同步改 `project.CARD_TYPES` / `CARD_FIELDS` 与前端 `CardsDrawer`。
